# 000 理念

> 语言：[中文](000-philosophy.zh-CN.md) · [English](000-philosophy.md)

dsh-superagent 是一个框架，也是一种与智能体协作的工作方式。它的核心原则是：

**尽可能少占用人的注意力，尽可能多地交付价值。**

项目中的每一部分都按它消耗的注意力来评判。一条消息、一条通知、一个问题、一个设置、一个面板元素、一段文档，各自都消耗某个人的注意力，因此每一项都必须给出超过这份消耗的价值，否则就删掉。

## 对智能体的要求

- **只在被请求时行动，或在书面规则允许时行动。** 一个请求只有在直接指向智能体、并且来自团队许可的人时才算数：此人在白名单上，或位于团队开放接受请求的会话中。没人要求的工作需要团队写下的规则，并且以只记录「智能体本来会做什么」的模式启动。
- **只在人必须行动、或能用到结果时才说话。** 它对一个请求只确认一次，并说明自己将做什么。工作时它保持安静。结果就绪时、需要决定时、或无法完成时，它才再次开口。消息简短，并发往提出请求的那个会话。
- **每次只问一个具体问题，** 并以结构化形式提出，让问题真正到达那个人，而不是留在长报告里。
- **以影响而不是投入来决定停在哪里。** 局部改动一直做到可评审的结果为止。需要设计决策的改动则以一个清晰的问题停下。
- **如实汇报。** 草稿标记为未完成，失败就报告为失败，永不为了回避提问而绕过某个限制。

## 对设计的要求

- **概念少。** 设计只包含它自己的领域概念（例如来源）及其具体实现（例如 GitHub 和飞书）。一个业务需求会成为其中某个概念的属性，或成为智能体遵循的提示词。设计不为它新增概念。
- **设置少。** 当某个值适用于几乎所有团队时，用默认值取代设置。团队用文字描述的行为是提示词文本，不是设置。
- **面板只显示需要人处理的东西。** 它先列出在等人的条目。健康状态不占空间。
- **文档按顺序阅读。** 每篇编号文档只建立在前面的文档之上，因此读者永远不需要一个尚未介绍的概念。

## 责任

智能体用你团队每天都能看到的账号发表评论、开启拉取请求、给人发消息。它发出的每条消息都消耗同事的注意力，而你要为此负责。智能体能做的事越多，其操作者对团队负的责任就越大：

- **从窄开始。** 先用一份很短的白名单，并让主动工作只被记录。等「智能体本来会做什么」看起来正确之后，再放宽这两者。
- **为更少的噪音调优。** 智能体吵闹时，把它的提示词改得更短更严，或暂停它。不要靠增加消息来解释噪音。
- **不要用它堆量。** 批量拉取请求、广播消息和无谓的忙碌，给团队带来的成本高于收益。
- **为它说的话负责。** 读一读智能体以你的名义发布的内容，发现错误时在提示词里纠正。

目标是在正确的时间给出正确的帮助，而在其他任何时间什么都不给。
